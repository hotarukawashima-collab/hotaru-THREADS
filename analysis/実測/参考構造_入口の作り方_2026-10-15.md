# A. 小さな行動 → 大きな変化の予感

**運用者の説明：玄関の塩、掃除、トイレ掃除。日常の小さな行動を入口にし、読者の好奇心を引き出す。**

## 型の特徴

```
・入口が「誰でも今日できること」になっている
・その行動そのものを教えるのではなく、行動を入口にして話を始める
・読者が「それだけでええの?」と思う落差が、読み進める力になる
```

## 冒頭の作り方

```
① 具体的な小さい行動を1つ置く   ← 説明ではなく、場面として
② 大げさにしない                「これだけで人生が変わる」と言わない
```

## 本文の展開

```
行動 → その行動の最中に何を思っていたか → 読者がどう受け取ってもいい形で閉じる
★ 行動 → 結果 の順にしない（下の禁止事項を見る）
```

## 連投のつなぎ方

```
1本目  行動を置いて、途中で切る
2本目  なぜその行動を選んだのか、本人の考え方を出す
★ 2本目を「やり方の手順」にしない。考え方で返す
```

## 目的への応用

```
集客    読者の日常にある行動（洗い物・洗濯・お茶をいれる）を入口にする
        ★ 行動を宿題にしない。「やってみて」で終えない
ファン化 なまけろ子がその場面で何を思っているかが主題になるとき
        → 判定は 15_生成フロー.md「ファン化の判定 ── 2段で見る」を使う
収益    有料noteのステップ3「今ある幸せを受け取る」「探す場所、夫と関係ないことでええんよ」と
        つながる場合のみ。★商品内容と購入導線が無ければ収益にしない
```

## なまけろ子の世界観との整合

```
⭕ 整合する   小さい行動そのものが、ステップ4「決めたあとは普通の一日を過ごしていい」と同じ向き
            701「4 普通に生活します」とも同じ

✕ 整合しない  行動をやったから現実が動く、という順番
            701は「望む → 現象」であって「行動 → 現象」ではない
            → 行動は、決めたあとに出てきたもののひとつとして置く
```

## 禁止事項

```
✕ 掃除・塩・片付けなどに開運効果があると書く
✕ 金運・夫の行動変化・夫婦仲の改善を、行動の結果として保証する
✕ 「毎日やること」として義務にする（701「メソッドも必要ありません」）
✕ 必要な現実的対応（話し合い・生活の問題・安全の確保）を、しなくていいと勧める
✕ 他人がやった行動を、なまけろ子がやったことにする
```

# B. 意外な断言 → 理由を連投で明かす

**運用者の説明：「嘘みたいな話だが」「あまり知られていないけれど」。
1投稿目で意外性と具体的なテーマを提示し、2投稿目で考え方や理由を説明する。**

## 型の特徴

```
・1本目は「意外だ」という合図 ＋ 何の話かを具体的に出す
・理由を1本目で言わない。2本目に置く
・★「意外性」だけで「具体的なテーマ」が無いと、ただの思わせぶりになる
```

## 冒頭の作り方

```
① 意外だという合図を短く置く
② ★同じ文の中に、何の話かを入れる
   → 初見の読者が「何の話か分からない」状態で切られないようにする
     （CLAUDE.md 初見テスト「投稿を初めて見る人にも、何の話か分かるか」）
```

## 本文の展開

```
1本目  合図 ＋ テーマ → 理由の手前で切る
2本目  なぜそう言えるのか、本人の考え方で返す
★ 2本目で「方法①②③」の手順書にしない
  （参考アカウント_目的別構造.md 4章：コアラもゆきぴも手順を入れていない）
```

## 連投のつなぎ方

```
・1本目の最後は、指示語で終えない
  → inspect.py の抽象語検査に当たる（「それ」「そこ」など）
  → 2026-10-15 の 15:00 で実際に止まった
・「〜よりも、」「〜のは、」のように、文の途中で切ると引きになる
・2本目の1行目が、1本目の最後の続きとして読めること
```

## 目的への応用

```
集客    読者が信じている「ふつう」を、具体的なテーマとセットで置く
ファン化 2本目が「なまけろ子はこう見てる」になるとき
収益    2本目が有料noteの章の中身に対応するときのみ。★商品内容と導線が要る
```

## なまけろ子の世界観との整合

```
⭕ 整合する   「夫の態度で判定しない」は、読者にとって意外な話として置ける
            07_引き寄せの方針_701.md の9「関連付けが現実を作る」

✕ 整合しない  意外性のために、根拠のない逆張りを書く
            （CLAUDE.md「〜ほど良くなる、の根拠のない逆張りになっていないか」）
```

## 禁止事項

```
✕ 「あまり知られていない」を、未確認の情報の裏づけとして使う
✕ 1本目で何の話か分からないまま切る（思わせぶりだけの引き）
✕ 2本目で、夫の行動や夫婦仲の改善を保証する
✕ 元投稿の言い回しをそのまま使う
```

# C. 実践 → 体感や変化 → 読者への一言

**運用者の説明：実際に行ったことや本人が感じたことを紹介し、
読者が自分の日常に当てはめられるようにする。**

## 型の特徴

```
・本人がやったこと → 本人が感じたこと → 読者へ短く返す
・★3つ目の「読者への一言」が、押しつけではなく許可や並走になっている
```

## 冒頭の作り方

```
① 本人がやったことを、1つだけ具体的に置く
   ★ 使えるのは、運用者が確認した内容だけ
     （参考アカウント_目的別構造.md 4章の「使える体験」）
```

## 本文の展開

```
やったこと → そのとき感じたこと → 読者へひとこと
★ 「やったから、こうなった」の因果にしない
  （CLAUDE.md「Aしたから、Bになった の因果の説明になっていないか」）
```

## 連投のつなぎ方

```
1本目  やったことと、感じたことの手前まで
2本目  感じたこと → 読者へのひとこと
★ 単発でも成立する型。無理に連投にしない
```

## 目的への応用

```
集客    読者が自分の日常に置き換えられる場面にする
ファン化 ★この型がいちばん向いている
        ただし「幸せな日常を並べただけ」ではファン化と判定しない
        → 15_生成フロー.md「ファン化の判定 ── 2段で見る」第2段で、
          本人の暮らし・感じ方・価値観が主題かを見る
収益    有料noteの7ステップのどれに当たるかを示せるときのみ
        ★幸せな場面＋プロフィール誘導だけでは収益にしない
```

## なまけろ子の世界観との整合

```
⭕ 整合する   「感じたこと」を書くのは、701「叶った私が味わっているだけ」と同じ扱い
            いい気分でも、そうでなくても、立場は取り消されない

✕ 整合しない  「心地よさを感じられたから叶った」という判定
            701「願望実現と激しい喜びはセットじゃない」（実践者編 5:30）
```

## 禁止事項

```
✕ 未確認の体験・夫のセリフ・数字・成果を創作する
✕ 参考アカウントの体験を、なまけろ子の実績に変換する
✕ 体感の有無を、引き寄せの成功・失敗の判定材料にする
✕ ネガティブな感情が出たことを、失敗の条件として書く
✕ 別居歴を毎回の投稿で繰り返す（CHARACTER.md:63-78）
```

# A・B・C に共通して守ること

```
1  投稿目的は 集客 / ファン化 / 収益 の3つだけ。A・B・C を目的として扱わない
2  型番号は増やさない。既存の型1〜型12の中で書く
3  「もう叶っている私を先に選ぶ」を崩さない（07_引き寄せの方針_701.md）
4  目の前の現実を、引き寄せの成功・失敗の判定材料にしない
5  ネガティブな感情を、失敗の条件にしない
6  必要な現実的対応を、しなくていいと勧めない
7  他人の体験を、本人の実績に変換しない
8  金運上昇・掃除による開運・夫の行動変化などの効果を保証しない
9  元投稿の文章・固有表現をコピーしない
10 未確認の体験談・数字・成果を創作しない
```
