# ③コンセプト設計:2つの分析 → knowledge/

## Claudeへの指示

`analysis/accounts/koara/analysis.md` と `analysis/accounts/yukipi/analysis.md` を読み、
「引き寄せ × 夫婦仲」の新アカウントの設計図を `knowledge/` の各ファイルに書いてください。

### 掛け合わせの方針

| | 役割 |
|---|---|
| **コアラさん** | **土台**。アカウント構造・投稿の型・文体・導線設計を、ここから移植する |
| **ゆきぴーさん** | **類似**。切り口や感情表現の引き出しとして参照する |
| **川島ほたる(運用者)** | 夫婦仲修復・離婚問題の**専門家**。ここが2アカウントにない唯一の資産 |

### 守ること

- **「コアラさんの構造 × 夫婦仲のテーマ」で作る。** 文言のコピーはしない。
  型(フックの作り方・展開・語尾・導線の置き方)を借りて、中身は夫婦仲の実体験・実務に置き換える。
- **各項目に必ず「根拠」を書く。** 「コアラ analysis.md の◯◯より」と出典を添える。
- **専門家であることを捨てない。** 引き寄せ系の「絶対大丈夫」「全部叶う」の断言をそのまま
  夫婦仲に持ち込むと、専門家としての信頼を毀損する場面がある(下記NGリスト参照)。
  **届く言い方と、守るべき一線の両立**が、このアカウントの差別化そのものです。

### 埋めるファイル

1. `knowledge/01_アカウント設計.md` — 表示名・アイコン・bio・リンク導線
2. `knowledge/02_文体ルール.md` — 一人称・語尾・読者の呼び方・絵文字
3. `knowledge/03_投稿の型.md` — フック型と展開型のカタログ(テンプレ付き)
4. `knowledge/04_ネタ地図.md` — 引き寄せ×夫婦仲のテーマ一覧
5. `knowledge/05_NGリスト.md` — 書かないこと・言わないこと

### 最後に

`knowledge/` が埋まったら、その内容を `generate_posts.py` の `SYSTEM_PROMPT` に
反映する差分を提案してください(勝手に書き換えず、提案してから確認を取ること)。
