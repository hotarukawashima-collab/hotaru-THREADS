**進行中の検証を、ここ1箇所にまとめる。**

---

## なぜこのファイルを作ったか(2026-10-09)

**検証の内容を、その日の投稿ファイル(`contents/投稿_YYYY-MM-DD.md`)にだけ書いていた。**

```
contents/投稿_2026-10-09.md
  「⚠ ラベル冒頭は検証を止めたわけではない。今日1日外して、差を見る」
  「★4回目。原稿どおりに出してほしい」
      ↓
翌日 投稿_2026-10-10.md を新しく作る
      ↓
持ち越しが落ちる
```

**日付ファイルは1日で役目が終わる。進行中のものを置く場所ではない。**

`11_再投稿.md` にも「現在の検証: 12:00 ラベル冒頭 / 23:00 CTA」と書いてあったが、
**23:00 CTAはもう結論が出ていて、15:00の切り分けが入っていなかった。古くなっていた。**

> **検証は、日付ファイルではなくここに書く。**
> **投稿を作るときは、`12_在庫表.md` の次にここを見る。**

---

## ⚠ 検証中のあいだ、守ること

```
1. 枠と型を動かさない   動くと前日との比較が成立しない
2. 原稿どおりに出す     書き換えると、型の問題か本文の問題か分からなくなる
3. その枠を再投稿に使わない
4. 結論が出たら、下の「終わった検証」に移す(消さない)
```

**ただし ——**

> **検証の都合を、投稿の質より上に置かない。**(`03_投稿の型.md`)
> 明らかに弱い原稿を「検証だから」で出すのは本末転倒。
> **弱いと分かったら、検証をいったん止めて理由を書く。**


# 終わった検証

## 23:00 CTA ── 結論: フォローは表示数が作る。CTAではない

```
10/4  表示2,656 / ♡23 / フォロー25人   ← 型5 + CTA
      ↓ 当初の結論「23:00の体験談+CTAはフォロー装置。ここは動かさない」
      ↓
10/8 訂正
      同じくらいの表示でCTA無しの投稿も、1本1フォロー付いていた
      25フォローを作ったのは表示2,656。CTAではない
```

```
10/6  表示523 / ♡8
10/7  表示409 / ♡2
10/8  表示502 / ♡3    ← 表示が落ちたらフォローも消えた
```

**コアラの実測でも裏付けがある。**

```
CTAを含む投稿           10本 / 357本(2.8%)
上位10本(♡681〜3,153)   CTAは1本も無い
```

**→ 23:00の型5固定もやめた(10/9)。枠の役目は「寝る前に安心して終われること」。**

## 更新のしかた

```
検証を始めるとき   「検証中」に項目を足す(枠・型 / 問い / 開始日 / 判断の分かれ方)
数字が出たとき     その項目に追記する
結論が出たとき     「終わった検証」に移す。★訂正があれば訂正も残す
```

**消さない。** 一度出した結論が間違っていたことが、何度もあった(23:00 CTAもそう)。
**訂正の履歴が残っていないと、同じ結論をもう一度出してしまう。**
